# 1. 引言

## 1.1 目的

本文档定义数心智能宠物健康平台（ShuxinPet）**宠物主端（APP）**的完整产品需求，明确功能范围、业务规则、交互逻辑与数据要求，作为研发、UI 设计、测试与运营验收的统一依据。文档以「分模块、分页面、分用户角色」的粒度描述需求，可直接拆解为开发任务与测试用例。

## 1.2 范围

本文档覆盖宠物主端全部功能，包括：账号与登录、首页、守护·健康监测、体征详情与趋势、运动详情与趋势、位置与历史轨迹、电子围栏、萌宠相册、宠圈社区、在线问诊、设备管理、宠物档案、健康报告、消息中心、我的与设置、AI 智能助手及占位功能。

# 2. 总体描述

## 2.1 产品视角

ShuxinPet 是以 Pet-S1 宠物智能项圈为硬件载体的一站式宠物健康守护平台。宠物主端 APP 面向宠物饲养人群，提供宠物健康监测、实时定位与轨迹、电子围栏、健康报告、AI 智能分析、在线问诊、宠物社区、设备管理与宠物档案等核心能力，帮助宠物主实现对宠物健康与安全的主动守护。

宠物主端在浏览器中以手机外壳（圆角机身 + 状态栏 + 灵动岛）呈现，底部导航为 **首页 / 守护 / 宠圈 / 我的** 四个 Tab，采用活力橙主题、欧美化极简交互风格，支持中英双语。

## 2.3 用户特征

| 用户角色 | 特征 | 使用场景 |
| ---- | ---- | ---- |
| 宠物主（新用户） | 首次使用，需完成注册、绑定设备、建档 | 注册、登录、引导绑定 |
| 宠物主（日常用户） | 高频查看健康、轨迹、社区 | 日常健康监测、轨迹查看、社区互动 |
| 宠物主（多宠物用户） | 名下多只宠物、多台设备 | 宠物切换、多设备管理、多宠物档案 |

用户特征假设：宠物主以移动端为主，操作以「查看」为主、低频编辑；对宠物健康数据敏感，需要及时异常提醒与趋势回顾；部分用户为海外用户，需要中英双语与邮箱 / 国际区号支持。

## 2.4 运行环境

| 项目 | 说明 |
| ---- | ---- |
| 呈现形态 | 移动端 APP（浏览器内手机外壳，限宽 402px） |
| 目标浏览器 | Chrome / Safari / Edge 最新两个大版本 |
| 前端技术栈 | Vue 3.5 + TypeScript + Vite + Vant 4 + Pinia + vue-i18n |
| 地图能力 | 高德地图 JS API（定位 / 轨迹 / 电子围栏） |
| 图表能力 | ECharts 5（健康曲线、运动趋势） |
| 数据来源 | 前端 mock 层（axios 自定义 adapter + 内存种子数据）模拟，无后端依赖 |

## 2.5 约束与假设

**约束：**

1. 硬件 Pet-S1 项圈通过蓝牙 / WiFi / 4G 上报体征与定位数据，本端仅消费数据，不直接控制硬件采集频率。
2. 地图能力依赖高德地图 JS API，需配置 `VITE_AMAP_KEY` 与 `VITE_AMAP_JSCODE`，未配置时地图区域展示友好提示。
3. 在线问诊、AI 分析等依赖平台服务与医生端协同，本端只负责提交与展示。

**假设：**

1. 宠物主名下最多绑定 3 只宠物（首页顶部头像栏最多展示 3 只）。
2. 单只宠物可绑定 0 或 1 台设备；设备与宠物为一对一绑定关系（冗余于宠物档案）。
3. 电子围栏固定围栏可创建多个，动态围栏（跟随手机）仅一条。
4. 健康报告由 AI 或本地规则引擎生成，宠物主只读查看，不可编辑。
5. 相册删除进入回收站，保留 1 个月后自动清除。

# 3. 功能需求

> 功能编号规则：`FR-PET-XXX`（XXX 为三位递增序号）。每个功能点按「功能描述 / 前置条件 / 操作流程 / 业务规则 / 异常处理」描述。

## 3.1 账号与登录

### 3.1.1 三端入口门户（FR-PET-001）

**功能描述**：首屏 `/` 提供宠物主 / 宠物医生 / 平台运营三端入口，用户点击对应入口进入该端登录页。同时兼容旧 `/login?role=` 入口，自动重定向到对应端登录页。

**前置条件**：无。

**操作流程**：

1. 用户访问平台首页，看到三端入口卡片（宠物主 / 宠物医生 / 平台运营）。
2. 点击「宠物主」进入 `/user/login`。

**业务规则**：

- 已登录且访问本端登录页时，自动跳转本端首页。
- 旧 `/login?role=xxx` 入口按角色参数重定向到对应端登录页。

**异常处理**：访问不存在路由跳转 404 页。

### 3.1.2 登录（FR-PET-002）

**功能描述**：宠物主通过密码登录或验证码登录进入系统。登录页支持 Tab 切换「密码登录 / 验证码登录」，展示本端演示账号卡片，可一键填入登录。

**前置条件**：用户已注册；协议需勾选。

**操作流程**：

1. 进入登录页，默认密码登录 Tab。
2. 输入账号 + 密码（可切换明文 / 密文），勾选服务协议与隐私政策，提交。
3. 或切换验证码登录 Tab，选择联系类型（手机号 / 邮箱）+ 国际区号，获取验证码（60s 倒计时），输入验证码提交。
4. 登录成功后写入登录态，跳转首页。

**业务规则**：

- 登录时强制校验账号角色与入口一致，角色错配提示「该账号不属于当前入口」。
- 勾选「记住我」登录态写入 `localStorage`（跨会话），否则仅写入 `sessionStorage`（当前标签页）。
- 演示账号卡片仅展示本端账号（`user` / `123456`），点击一键填充。
- 验证码登录成功后，若账号无密码，在设置页不展示「修改密码」入口。

**异常处理**：账号或密码错误、验证码错误、账号被禁用时，给出对应错误提示并保留已输入内容；验证码过期提示重新获取。

### 3.1.3 第三方登录（FR-PET-003）

**功能描述**：提供 Google / Apple 第三方登录按钮（占位）。

**前置条件**：已配置对应第三方 OAuth 凭据。

**业务规则**：首次第三方登录需补充绑定手机号 / 邮箱完成注册；已绑定账号直接登录。

### 3.1.4 注册（FR-PET-004）

**功能描述**：新宠物主通过手机号或邮箱完成注册。

**前置条件**：无。

**操作流程**：

1. 进入注册页，选择联系类型 Tab（手机号 / 邮箱）+ 国际区号（18 个国际区号）。
2. 输入手机号 / 邮箱，获取验证码（60s 倒计时）。
3. 输入验证码 + 密码 + 确认密码，提交注册。

**业务规则**：

- 密码规则：6–20 位，须同时包含字母与数字。
- 手机号 / 邮箱须唯一，已注册账号不可重复注册。
- 需勾选服务协议与隐私政策后方可提交。

**异常处理**：验证码错误 / 过期提示重新获取；账号已存在提示直接登录；两次密码不一致提示重新输入。

### 3.1.5 找回密码（FR-PET-005）

**功能描述**：宠物主通过验证码重置登录密码。

**操作流程**：

1. 进入找回密码页，输入手机号 / 邮箱 + 验证码（scene=reset）。
2. 输入新密码 + 确认新密码，提交重置。
3. 重置成功后跳转登录页。

**业务规则**：验证码 scene 标记为 reset；账号不存在时拦截并提示；新密码规则与注册一致。

### 3.1.6 用户协议与隐私政策（FR-PET-006）

**功能描述**：提供用户协议与隐私政策文档的查看入口。

**操作流程**：在登录 / 注册页点击「服务协议」「隐私政策」链接，进入 `/agreement/:type` 查看详情。

**业务规则**：协议内容中英双语；注册 / 登录须勾选同意后方可提交。

## 3.2 首页

### 3.2.1 宠物切换与添加（FR-PET-007）

**功能描述**：首页顶部横向头像栏展示名下宠物（最多 3 只），点击切换当前宠物；末尾「+」跳转添加宠物页。

**前置条件**：已登录。

**操作流程**：

1. 进入首页，顶部展示宠物头像栏，当前宠物高亮。
2. 点击其他宠物头像切换当前宠物，首页健康数据随之切换。
3. 点击「+」跳转 `/pets/add` 添加宠物。

**业务规则**：名下最多 3 只宠物；切换宠物后，健康卡片、宫格、快捷入口均以当前宠物为上下文。

### 3.2.2 宠物健康概览卡片（FR-PET-008）

**功能描述**：首页核心信息大卡片展示当前宠物物种图标、名称、性别、年龄、品种、体重（kg）、洗澡 / 驱虫 / 疫苗计数。

**操作流程**：进入首页查看；点击卡片可跳转宠物档案页。

**业务规则**：体重单位 kg；洗澡 / 驱虫 / 疫苗计数来自宠物档案护理记录；无宠物时展示空态引导建档。

### 3.2.3 功能模块宫格（FR-PET-009）

**功能描述**：首页 2×2 宫格提供「萌宠相册」「待办记录」等入口，跳转对应页面。

**业务规则**：相册跳转 `/album`；待办记录为占位页。

### 3.2.4 底部快捷操作栏（FR-PET-010）

**功能描述**：首页底部快捷入口提供「在线问诊 / AI 助手 / 爱宠食谱 / 宠语翻译 / 健康自检」。

**业务规则**：在线问诊跳转问诊记录页；AI 助手跳转 `/assistant`；爱宠食谱、宠语翻译、健康自检为占位页。

### 3.2.5 汉堡菜单（FR-PET-011）

**功能描述**：首页右上角汉堡菜单支持语言切换与宠物管理入口。

**操作流程**：点击汉堡菜单，弹出面板，可切换语言（中 / 英）、进入宠物管理。

### 3.2.6 无宠物 / 无设备占位（FR-PET-012）

**功能描述**：无宠物或无设备时，首页与守护页展示基础布局与「--」占位，引导用户建档或绑定设备。

**业务规则**：无宠物时健康卡片、守护页指标均以「--」占位并引导添加宠物 / 绑定设备；占位不阻断其他功能使用。

## 3.3 守护·健康监测

### 3.3.1 实时地图与轨迹（FR-PET-013）

**功能描述**：守护页全屏高德地图展示宠物当前定位、轨迹连线与电子围栏范围，支持宠物 Tab 切换监测对象。

**前置条件**：已绑定设备且设备在线。

**业务规则**：地图未配置高德 Key 时展示友好提示；轨迹连线由定位点按时序连接；围栏范围以圆形覆盖物展示。

### 3.3.2 宠物头部信息与设备状态（FR-PET-014）

**功能描述**：守护页顶部展示宠物头像 / 名称 / 项圈设备名 / 设备状态标签（在线 / 离线 / 低电量 / 未绑定）。

**业务规则**：设备状态四态：在线、离线、低电量、未绑定；未绑定设备时提示绑定。

### 3.3.3 健康指标实时卡片（FR-PET-015）

**功能描述**：守护页展示体温 / 心率 / 血氧 / 呼吸 / 卡路里五项生命体征实时卡片，点击进入对应体征详情页。

**业务规则**：指标实时刷新；异常值按健康等级着色（正常绿 / 预警橙 / 危险红）；点击跳转 `/health/vitals/:petId/:metricType`。

### 3.3.4 运动指标实时卡片（FR-PET-016）

**功能描述**：守护页展示步频 / 步幅 / 步态 / 速度四项运动指标实时卡片，点击进入运动详情页。

**业务规则**：点击跳转 `/health/exercise/:petId/:metricType`；步态取值（慢走 / 走 / 跑 / 静止）。

### 3.3.5 电子围栏入口（FR-PET-017）

**功能描述**：守护页提供电子围栏快捷入口，带固定围栏数量角标，跳转围栏管理页。

**业务规则**：角标展示当前宠物固定围栏数量；点击跳转 `/health/fence/:petId`。

### 3.3.6 语音对讲（FR-PET-018）

**功能描述**：守护页支持按住说话（MediaRecorder 录音）、上滑取消、模拟对方回复（语音播报）。

**操作流程**：

1. 按住「按住说话」按钮开始录音。
2. 上滑取消发送；松开发送。

# 4. 非功能需求

## 4.1 性能需求

1. 页面首屏可交互时间目标 ≤ 2s（4G 网络）；轨迹、趋势图等数据密集页面 ≤ 3s。
2. 历史轨迹抽稀后最多渲染 150 个轨迹点，保证地图交互流畅。
3. 列表分页加载，单页默认 pageSize 合理（如 10–20 条），上拉无限加载无卡顿。
4. 健康曲线采用 ECharts 平滑渲染，单图数据点 ≤ 2000。

## 4.2 安全性需求

1. 登录鉴权：请求携带 `Authorization: Bearer <token>`，按 token 解析用户并校验登录态与角色。
2. 密码采用 BCrypt 等不可逆加密存储；手机号、邮箱等敏感信息加密存储。
3. 角色隔离：宠物主端路由强制校验 `role === 'user'`，跨端访问重定向到本端首页。
4. 注销账号后个人数据保留 180 天后彻底删除，符合法律合规要求。

## 4.3 可靠性需求

1. 数据变更（绑定 / 解绑、围栏增删改、社区点赞关注、下单、删除报告等）即时生效并回读校验。
2. 网络异常、接口失败提供统一错误提示与重试入口。
3. 关键操作（删除宠物、删除围栏、注销账号、彻底删除相册）需二次确认。

## 4.4 可用性需求

1. 界面遵循欧美化极简风格，主色活力橙；关键操作明确、反馈及时。
2. 支持中英双语无缝切换，词条 key 完整对齐。
3. 空态、加载态、错误态均有明确视觉反馈。

## 4.5 兼容性需求

1. 兼容 Chrome / Safari / Edge 最新两个大版本。
2. 移动端外壳限宽 402px，适配主流手机宽度。

## 4.6 国际化需求

1. 全端中英双语，通过 vue-i18n 管理，词条可在运营端运行时编辑。
2. 国际区号支持 18 个常用国家 / 地区；注册登录邮箱优先。

# 5. 接口需求

## 5.1 用户接口

1. 统一响应包：`{ code, data, message }`，`code === 0` 表示成功，前端响应拦截器自动解包，页面拿到纯 `data`。
2. 统一鉴权：请求拦截器附加 `Authorization: Bearer <token>`。
3. 分页接口统一参数 `{ page, pageSize, keyword?, status? }`，返回 `{ list, total, page, pageSize }`。
4. 模拟延迟 150–500ms，贴合真实网络体验。

## 5.2 软件接口

1. 高德地图 JS API：定位、轨迹、电子围栏（`VITE_AMAP_KEY` / `VITE_AMAP_JSCODE`）。
2. ECharts 5：健康曲线、运动趋势图表。
3. 浏览器 MediaRecorder：语音对讲录音；Web Speech API：AI 助手语音输入。
4. vue-i18n：中英文词条加载与运行时覆盖。

## 5.3 通信接口

1. 设备数据经蓝牙 / WiFi / 4G 上报至平台，本端通过接口拉取体征、定位、运动数据。
2. 远程指令（响铃 / 警示灯 / 请求定位）通过平台下发至设备。
3. 在线问诊、健康数据推送通过平台与医生端协同。

# 7. 其他需求

## 7.1 法律与合规需求

1. 注册 / 登录须勾选用户协议与隐私政策。
2. 宠物医疗类内容（AI 结论、医生意见）须标注「仅供参考，不替代兽医诊断」。
3. 用户个人信息（手机号、邮箱）加密存储，遵循数据最小化与注销删除要求。

## 7.2 业务规则

1. 宠物主名下最多 3 只宠物；单宠物最多绑定 1 台设备。
2. 电子围栏固定围栏可多个，动态围栏仅 1 条，动态围栏半径 100–3000m。
3. 密码规则：6–20 位须含字母与数字。
4. 健康评分 <85 展示警示色；综合评级 A/B/C/D 按健康分析规则体系判定。
5. 问诊病情描述必填、最长 500 字。

## 7.3 算法与计算需求

健康报告与 AI 分析依据《宠物健康数据分析规则体系（行业修订版 v2.1）》：

1. **时间粒度**：支持 day（单日）/ week（近 7 天）/ month（近 30 天）三档，聚合方式为「先算每日中位数，再取多日中位数」，剔除 ±2SD 离群值，生理指标优先取静息时段。
2. **体温标准**：临床标准区间 38.0–39.2℃。
3. **心率分层**：按大 / 中 / 小型犬 + 猫分层，幼老年修正。
4. **血氧阈值**：<95% 即「关注」，<90% 危急。
5. **卡路里公式**：RER = 70×W^0.75，DER = RER×生命阶段系数，区分总消耗与活动消耗。
6. **运动指标**：个体基线对比 + 步态对称性分析。
7. **综合评级**：关注 ≠ 异常，减少过度预警；危急指标一票升级 D 级。
8. **就医提示**：按紧急程度 routine / urgent / emergency 分级，附建议检查项。
